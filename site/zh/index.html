为什么做它

一个 AI 编程会话，是活在终端窗口里的一段对话。关了窗口、改了目录名、重启了电脑，对话其实还在磁盘上，只是没有东西再指向它了。makit 换了一个单位：会话本身是对象，不是窗口。它读 Claude Code 和 Codex 本来就写在磁盘上的会话文件，所以不管会话是在哪个终端里起的，都列在这里。

Unix 作业控制makit
jobs：列出作业和状态会话列表：运行中 / 等你 / 空闲 / 已停止 / 已归档
Stopped (tty input)：卡在等你输入等待审批 / 等待回答，并通知
fg %n：拉回前台一键恢复，回到原来的目录
终端一关，作业就没了记录在磁盘上：窗口关了、重启了、目录改名了都还在

它能做什么

  • 不再弄丢会话扫描 ~/.claude 和 ~/.codex，按项目或状态分组，跨全部会话搜索。任何终端里起的会话都会出现。
  • 知道谁在等你每个会话一个状态点；等审批或等你回答时弹桌面通知（Claude Code，在设置里安装 hook）。
  • 接着上次聊在原来的工作目录里恢复。目录被删或搬走了，makit 会重建链接，Claude Code 的会话不会丢。
  • 把对话重排着读实验功能，默认关。历史从会话文件按当前窗口宽度重新排版，活动的那一段仍是真终端。
  • 分屏终端树形分屏，拖动调大小，一个屏幕盯住多个会话。
  • 本地、不上传只读你本机的会话文件。没有账号，没有遥测，不上传任何内容。
  • 原生、轻Rust + GPUI，不是套壳网页。内存约 55–75 MB，5,000 个会话不到一秒就绪。
  • 21 套主题，中文 / English主题跟随系统明暗；可以导入 iTerm2 配色。
  • 自带更新检查新版本并原地替换；用 Homebrew 装的就 brew upgrade。

安装

主要是 macOS 版；Windows 是预览版，Linux 计划 0.3。

macOS

下载 .dmg，打开后把 makit 拖进「应用程序」。

下载 macOS 版

-universal 通用包所有 Mac 都能用；Apple 芯片和 Intel 单架构包体积约一半。

Homebrew

brew install --cask nicholas-hoult/tap/makit

Windows（预览版）

一个带 makit.exe 的 .zip，未签名，部分功能还是占位。Windows SmartScreen 会拦一次：更多信息 → 仍要运行。

下载 Windows 版

第一次打开：这个包还没有 Apple 签名，macOS 会拦一下。到 系统设置 → 隐私与安全性 点 仍要打开；如果提示「已损坏」，在终端运行 xattr -dr com.apple.quarantine /Applications/makit.app。应用内更新下载的文件不会再被拦。

常见问题

和终端、终端复用器有什么不同？

makit 也有分屏终端，但它是围绕会话组织的，不是围绕窗口：不管会话在哪里起的都会列出来，保留它们的历史，告诉你哪一个在等你。和你喜欢的终端搭配着用就行。

支持哪些 agent？

Claude Code 和 Codex。状态和通知目前只有 Claude Code；Codex 的会话可以列出和恢复。

会上传我的会话吗？

不会。它只读本地文件。检查更新只请求版本信息，不会发送任何会话内容、路径或项目名。

它会读写我机器上的哪些东西？

读 ~/.claude/projects、~/.claude/sessions 和 ~/.codex/sessions；自己的数据在 ~/.claude/makit；只有你点「安装 hook」时才会碰 ~/.claude/settings.json。README 里有完整清单。

删掉 makit，会话会丢吗？

不会。会话属于 Claude Code 和 Codex，原地不动。删 ~/.claude/makit 只会清掉 makit 自己的设置和归档标记。

为什么没有签名？

还没有 Apple 开发者账号。第一次打开的放行步骤见「安装」。应用内更新下载的文件不会再被拦。

Windows 和 Linux 呢？

Windows 从 0.1.5 起有预览版（能运行，部分功能还是占位）；Linux 计划 0.3。
